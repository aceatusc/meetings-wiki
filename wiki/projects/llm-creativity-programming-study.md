# LLM Creativity Programming Study

## Summary

This study examines how LLM assistance affects creative programming behavior. The emerging thesis is a [[productivity-creativity-tradeoff|productivity-creativity tradeoff]]: LLM assistance can produce more correct and complete outputs under limited time, while reducing ideation time, creative moments, and possibly creative ownership.

## Broader Motivation

The broader agenda is [[mixed-initiative-collaboration|bidirectional or mixed-initiative human-AI collaboration]]. Current tools often operate one-way: the human asks, the AI responds, and the human accepts, rejects, or monitors. The study contributes to the human-side understanding needed before designing better AI-side interventions.

## Research Questions

From the transcript, the study asks:

- How does LLM assistance affect creative solutions?
- What are the effects of LLM usage on creativity during the problem-solving process?
- How can LLMs support creativity in LLM-assisted programming?

## Method

- Participants: 20 final participants, after 3 of 23 dropped.
- Design: between-subjects programming experiment.
- Tasks: one algorithmic task and one system design task.
- Conditions: GitHub Copilot available versus no assistant; external resources restricted to isolate LLM effects.
- Data: screen recordings, think-aloud protocol, final code submissions, and retrospective interviews.
- Analyses: action coding, behavioral coding, thematic analysis, code quality/characteristics, correctness and completeness, unique ideas, code similarity, and creative/aha moment coding.

## Findings From Presentation Draft

- LLM-assisted solutions had more function calls and more lines of code.
- LLM-assisted solutions were reported as less maintainable.
- LLM-assisted solutions were more correct and complete under the session's time constraints.
- Solution diversity did not clearly improve with LLM assistance.
- Participants spent significantly less time on idea generation when using the LLM.
- Participants experienced fewer creative or aha moments across most stages.
- Collaboration modes were identified around the AI's role: brainstormer, verifier, implementer, and a fuller AI-driver/backseat pattern.

## Presentation Guidance

- Keep the broad bidirectional-collaboration setup short.
- Lead quickly into creativity and the productivity-creativity tradeoff.
- Do not label code metrics as creativity or usefulness unless the link is defended.
- Use maintainability as the clearest bridge to usefulness.
- Flash methodology once, then explain relevant methods inside each research question.
- Define cognitive alignment if keeping the term; otherwise consider control, orchestration, or mixed initiative.
- Label collaboration modes as AI roles to avoid confusion.
- Add a future-directions ending that reconnects to broader mixed-initiative collaboration.
